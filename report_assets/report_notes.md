## 1. Introduction to PCA, SVD and SVM

- PCA via SVD: centre the feature matrix X (n x p), X = U S V^T, the principal axes are the rows of V^T, the variance along axis k is s_k^2 / (n - 1). `SVDPCA` in `src/sentinel/svdpca.py` does exactly this with `numpy.linalg.svd`; `tests/test_svdpca.py` checks it against `sklearn.decomposition.PCA` (components equal up to sign).
- Truncated SVD works on the uncentred matrix; the first component then mostly carries the mean (level) rather than the variance. This project compares both (M2).
- Eckart-Young: keeping the k largest singular values gives the best rank-k approximation in the Frobenius norm. Used here for denoising a magnitude spectrogram (keep k singular values by cumulative energy or by the elbow).
- SVM: maximum-margin classifier; the RBF kernel K(x, y) = exp(-gamma ||x - y||^2) handles non-linear boundaries; C trades margin against training errors; `class_weight=balanced` offsets the class imbalance. Platt scaling maps the SVM score to a probability.
- On this data, 146 z-scored features need 66 components for 90% of the variance, 85 for 95%, 119 for 99% (denoising variant none). The first component carries 30.1% of the variance; its largest loadings are dmfcc10_std, dmfcc08_std, dmfcc09_std (frame-to-frame spectral change, not loudness: Spearman with window rms +0.06). PC2 is partly a loudness axis (Spearman with window rms -0.58).

## 2. Problem statement

- Task: classify 1 s windows (0.5 s hop, 16 kHz mono) and turn window probabilities into alerts and events a person on watch can use (perimeter surveillance framing).
- Classes: aircraft, ambient; alert target class: aircraft. A drone class is the intended third class but no drone data was available.
- Data: 960 ESC-50 clips from 707 source recordings. Aircraft 80 files (720 windows), ambient 880 files (7920 windows); 240 of the ambient files are hard negatives (engine, train, vacuum cleaner, washing machine, chainsaw, hand saw).
- Used for training and CV after the silence gate: 8273 windows (712 aircraft, 7561 ambient). The aircraft class is 8.6% of windows.
- No leakage: grouped splits on the Freesound source recording id (StratifiedGroupKFold, 5 folds, seed 1337).

## 3. Implementation details

- Preprocessing: resample to 16 kHz, DC removal, Butterworth band-pass 100 to 7000 Hz (order 4, second-order sections); zero-phase `sosfiltfilt` offline, causal `sosfilt` with carried state live.
- Causal versus zero-phase filter: grouped-CV balanced accuracy 0.791 (zero-phase), 0.791 (trained zero-phase, tested causal); fold-paired change -0.0007.
- Noise reduction, all from scratch: spectral subtraction, Wiener gain, truncated-SVD denoising of the magnitude spectrogram (energy target and elbow).
- Features: 146 per window (20 MFCC with delta and delta-delta as mean and std, spectral centroid, bandwidth, rolloff, flatness, contrast, zero-crossing rate, RMS). Standardised on the training folds only.
- Saved model: denoising none, PCA 40 components, RBF SVM C=1.0, class weight balanced, Platt calibration fitted on out-of-fold scores. It is the untuned default fixed before the ablation ran.
- Ablation: 150 configurations (denoising x level features x PCA size x kernel/C), same grouped folds for all. Best cell svd_elbow, PCA 20, rbf: balanced accuracy 0.815, optimistic because it was chosen on the data it is scored on; nested CV gives 0.763 pooled.
- Alert logic (`src/sentinel/alerting.py`, pure functions): EMA alpha 0.5, ON when 3 of the last 5 smoothed windows are at or above t_on, OFF after 4 windows below t_off = 0.6 t_on, minimum event 2.0 s, merge gap 3.0 s. Engineering values, not tuned.
- Event feed: events.jsonl and events.csv per run, and an optional ZeroMQ PUB stream (`tcp://127.0.0.1:5556`, topic `acoustic`, two frames: topic and JSON).

## 5. Results and discussion

- Window classifier, grouped CV (default pipeline): balanced accuracy 0.791 ± 0.042; aircraft recall 0.750, aircraft precision 0.298, AUC 0.878; specificity on hard negatives 0.730 (plain ambient 0.872). Label-permutation check: 0.576, 0.468, 0.499 (chance level is 0.5).
- Alerts at the model threshold (t_on 0.303): 29.5 false alarms per hour on 1.22 h of esc50_crossfit audio, mean event recall 0.120.
- Operating point under the rule at most 1 false alarm per hour with the best mean event recall: t_on 0.56, 0 false alarms in 1.22 h (95% upper bound 3.0 per hour), mean event recall 0.015.
- Recall for other false-alarm budgets: 1/h: t_on 0.56, recall 0.015; 5/h: t_on 0.46, recall 0.025; 10/h: t_on 0.44, recall 0.045; 30/h: t_on 0.30, recall 0.120; 100/h: t_on 0.14, recall 0.555.
- Event recall by scenario SNR at the operating point: +20 dB 0.075 (3/40), +10 dB 0.000 (0/40), +5 dB 0.000 (0/40), +0 dB 0.000 (0/40), -5 dB 0.000 (0/40).
- Discussion points: the window classifier is weak at event level (a property of the model and data, not of the unit-tested alert logic); the alert parameters were not tuned and could move the trade-off; part of the low-SNR recall at low thresholds is chance, because the background itself raises false alarms.
- Event SNR estimate: validated against pink noise in M5 (bias about +0.8 dB at +10 dB nominal), but not meaningful on the ESC-50 scenario streams. SNR est. is a power-subtraction estimate against the 10th percentile of recent frame power. It is meaningful only when the background has a steady noise floor. On ESC-50 streams (clips of very different levels joined together, some padded with digital silence) the floor is pulled far below the typical background and the estimate is much too high, so do not quote it from such a run.
- Honest limits: no real long recordings, so the false-alarm rate comes from ESC-50 clips only (abruptly joined clips, a stress test) and the 1 per hour target is not validated on continuous audio.
- Range model: the condition `recall >= 0.90` is never met (best recall 0.075 on `m6_event_recall_at_operating_point`), so snr_min is reported as not reached and the range is shown only as a sensitivity table for hypothetical required SNRs. The drone source level is not assumed (TODO_CITE).
- Bench distance test: no bench recordings were made, so nothing is claimed about measured distances.
- Calibration caveat: probabilities are calibrated for clean ESC-50 audio at ESC-50 prevalence. The saved model is in-sample on ESC-50; all accuracy numbers come from grouped CV or cross-fitted models.

## 6. Conclusion

- What works: a complete, tested chain from audio to events (filtering, MFCC features, PCA via SVD, SVM, calibrated probabilities, alert logic, event feed) that runs 104 times faster than real time on a laptop CPU.
- What the numbers say: window-level balanced accuracy 0.79 on ESC-50 aircraft versus ambient; at one false alarm per hour the event recall is 0.015. The chain is sound, the classifier is the weak part.
- Next steps: add real drone recordings with a licence that allows this use, validate false alarms on at least one hour of continuous site audio, tune the alert parameters on that audio, and measure the source level and range.
